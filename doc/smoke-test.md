# 冒烟测试清单（Smoke Test）

> 每次发版前过一遍。对应 v0.0.24–v0.0.26 的全部修复点；标 ⭐ 的是曾出过 bug 的高风险路径。
> 环境要求：Thunderbird 121+，已配置好可用的 LLM 提供商（本地 Ollama 即可）。

## 0. 安装与启动

- [ ] Remove 旧扩展 → Load Temporary Add-on 加载新 zip（或正式安装 xpi）
- [ ] Debug Add-ons → Inspect：background 控制台无红色报错
- [ ] 默认标签（Advertisement / Business / Service Important）已在 Thunderbird 标签列表中创建

## 1. 批量打标主流程

- [ ] 选中 3–5 封 → 工具栏按钮 → 面板在**本窗口**以标签页打开
- [ ] 「开始 AI 打标」→ 进度条推进 → 进入确认页
- [ ] ⭐ 确认页滚到最底部，点最后一封的 **+ 添加**：标签菜单完整可见（向上翻转），无需滚动
- [ ] 列表顶部第一封点 **+ 添加**：菜单向下展开，完整可见
- [ ] 菜单中**没有**「处理失败 / Processing Failed」
- [ ] 增删标签 → 应用 → 完成页 `成功 + 失败 = 选中数`

## 2. 取消与统计 ⭐

- [ ] **分析中途取消**：进度立即停止；完成页失败数不含被取消的在途请求
- [ ] **应用中途取消**：未处理项计入失败；`成功 + 失败 = 总数`
- [ ] 取消后能立即重新开始（面板不卡死、不残留 applying 状态）
- [ ] 故意停掉 LLM 服务再跑一批：连续 3 封失败后整批中止进错误页；**点重试可正常重跑**

## 3. 动作模式与移动

- [ ] 仅打标：只写标签，不移动
- [ ] 打标 + 移动：标签对应文件夹被创建（auto 模式），邮件移动后标签仍在
- [ ] 仅移动：无目标文件夹标签的邮件计为失败并提示

## 4. QQ / Gmail 账户（如有）

- [ ] tag-only 模式跑 QQ/Gmail 邮件：明确计为**失败**并显示服务器不支持原因（不是"全部成功"）
- [ ] 打标+移动模式：跳过打标但正常归档，完成页有跳过说明

## 5. 多窗口 ⭐

- [ ] 两个 Thunderbird 窗口（不同账户）各点工具栏按钮：**各自有独立面板**，互不跳转
- [ ] 窗口 B 批次出错后点「重试」：重试的仍是窗口 B 的邮件

## 6. 确认页编辑保留 ⭐

- [ ] 确认页修改某封的标签 → **关闭面板标签页** → 重新打开：修改还在

## 7. 设置页

- [ ] 切换提供商、改 Base URL → 完整请求地址预览实时更新
- [ ] **Reset**：恢复默认值，预览/警告同步刷新，无报错
- [ ] 把云端提供商 Base URL 改为非官方主机：出现红色第三方主机警告；改回默认：警告消失
- [ ] 测试连接 / 获取模型：失败时 Toast 12 秒自动消失且可点 × 关闭；切换提供商后旧请求结果不再弹 Toast
- [ ] 标签导入导出 / 诊断 / 重置降级名单正常

## 8. 语言

- [ ] 设置页切换中/英：界面即时切换
- [ ] 切换后**不重启**跑一批：后台通知、确认页「（自动创建）」等文案跟随新语言

## 9. 摘要窗口

- [ ] 邮件工具条按钮 → 摘要正常显示；建议标签可点击应用
- [ ] 「翻译这封邮件」正常；复制按钮有「已复制」反馈
- [ ] 摘要失败时错误原因可见（不只是通用提示）

## 10. 提供商（按可用性选测）

- [ ] Ollama（本地）
- [ ] Custom 网关（OpenAI 兼容）
- [ ] Gemini ⭐（v0.0.24 修复协议错误，若可用务必测）
